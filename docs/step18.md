# 18단계 — RAG 보강: 하이브리드 검색 · 리랭킹 · 쿼리 확장 (체크리스트 #3, 필수)

체크리스트 #3 은 "기본 벡터 검색" 이 아니라 **하이브리드 검색 · 리랭킹 · 쿼리 확장**을
요구한다. 지금은 `MemoryStore.search` 가 Chroma 벡터 검색 한 번으로 끝난다.

## 먼저 짚어야 할 것 — 검색은 어제까지 죽어 있었다

17단계에서 `embed_query` 누락으로 **검색이 한 번도 동작하지 않았다는 것**을 발견해 고쳤다.
즉 이 프로젝트의 벡터 검색은 **아직 실제 데이터로 한 번도 평가된 적이 없다.** 그 위에
하이브리드·리랭킹을 얹으면 무엇이 기여하는지 알 수 없는 상태로 기계장치만 늘어난다 —
검증되지 않은 `--merge-threshold 0.3` 에서 이미 겪은 문제다.

그래서 이번 단계는 **기여도를 측정할 수 있게** 만드는 것을 설계 원칙으로 둔다.

- 벡터 단독 결과를 **기준선으로 함께 계산**하고, 최종 순위와 나란히 리포트에 남긴다.
- 각 단계(벡터·BM25·확장 질의)가 어떤 문서를 몇 위로 올렸는지 기록한다.
- 그래서 한도가 회복된 뒤 온라인 실행 한 번으로 "하이브리드가 실제로 도움이 됐는가" 를
  주장이 아니라 숫자로 판단할 수 있다.

## 결정 1 — 하이브리드: BM25 + 벡터를 **RRF** 로 합친다

`rank_bm25` 가 이미 설치돼 있다(ragas 의존성). 새 의존성이 필요 없다.

**점수를 직접 더하지 않고 순위로 합친다(Reciprocal Rank Fusion).**

```
score(d) = Σ 1 / (k + rank_i(d)),  k = 60 (관례값)
```

이유는 **코사인 거리와 BM25 점수가 서로 비교 불가능한 척도**라는 데 있다. 가중 합으로
섞으면 가중치라는 검증되지 않은 상수가 또 하나 생기고, BM25 점수는 코퍼스에 따라 범위가
달라져 그 가중치가 데이터마다 어긋난다. RRF 는 순위만 쓰므로 척도 문제가 사라지고 조정할
값이 없다.

BM25 코퍼스는 `collection.get()` 으로 전체 문서를 가져와 메모리에서 만든다. 저장 문서는
한 줄 요약이고 지금 2건이라 문제가 없다. **수천 건 규모가 되면 다시 볼 지점**이므로
주석으로 남긴다.

## 결정 2 — 리랭킹: 새 모델을 쓰지 않고 도메인 신호로 한다

cross-encoder 리랭커는 `sentence_transformers` 가 필요한데 설치돼 있지 않고 무겁다.
LLM 리랭커는 토큰을 쓰고 **17단계의 축약 경로에서 동작하지 않는다.**

이 도메인에는 더 나은 신호가 이미 있다.

| 신호 | 왜 |
|---|---|
| **`occurrences`** | 이 코드베이스가 **반복하는 실수**일수록 먼저 볼 만하다. 원본 노트북이 못 했던, 이 프로젝트만의 신호다 |
| **언어 일치** | `--cross-language` 로 격리를 풀었을 때, 같은 언어 사례를 위로 올린다 |
| **최근성(`last_seen`)** | 오래 안 터진 패턴보다 최근 것이 지금 코드와 가깝다 |

RRF 융합 점수에 이 신호들을 **곱셈 보정**으로 얹는다. 덧셈이면 보정이 원래 순위를 뒤집을
수 있는데, 곱셈이면 순위를 크게 흔들지 않으면서 동순위를 가른다.

## 결정 3 — 쿼리 확장: 15단계의 구조화 출력을 재사용한다

새 LLM 호출을 추가하지 않는다. `BugPattern` 이 이미 세 갈래로 나뉘어 있다.

```
pattern        경계 검사 누락
symptom        IndexError: list index out of range
cause_and_fix  범위를 확인한 뒤 기본값을 반환한다
```

**이 세 면을 각각 질의로 던져 결과를 RRF 로 합친다.** 하나의 긴 문장으로 던지면 세 면이
평균되어 흐려지는데, 나눠 던지면 "증상으로 찾기" 와 "해결 방법으로 찾기" 가 각각 살아난다.
LLM 호출은 지금과 같이 1회다.

**규칙 기반 확장도 함께 둔다.** 축약 경로(LLM 없음)에서도 확장이 동작해야 한다.

- 테스트 출력에서 예외 이름을 뽑는다 (`IndexError`, `KeyError`, `TypeError` …)
- 대상 파일명과 언어

## 구현 중 확인한 것 — 코퍼스가 작으면 BM25 는 침묵한다

메모리가 1~2건일 때 `bm25_rank` 가 `None` 으로 나오는데, **버그가 아니라 BM25 의 성질**이다.
IDF 는 "이 단어가 몇 개 문서에 있는가" 로 희소성을 재므로, 문서가 몇 건뿐이면 모든 단어가
사실상 전체 문서에 있어 IDF 가 붕괴한다. 실측값이다.

| 코퍼스 | "경계 검사 누락" 질의 점수 |
|---|---|
| 1건 | **-0.824** |
| 2건 | 0.0 |
| 3건 | 1.532 |

그래서 초기에는 벡터 검색이 단독으로 일하고, 패턴이 쌓이면서 BM25 가 기여를 시작한다.
`bm25_rank: None` 을 고장으로 오해하지 않도록 코드 주석과 이 문서에 남겼다.

## 보류

- **온라인 실측** — 하이브리드가 실제로 도움이 됐는지는 자격증명·한도가 회복된 뒤 판단한다.
  이번 단계는 그 판단을 **가능하게 만드는 것**까지다. 기준선(벡터 단독) 순위를 함께 남기는
  이유가 그것이다.
- **cross-encoder 리랭커** — `sentence_transformers` 의존성이 필요하고 무겁다. 도메인 신호
  리랭킹의 실측 결과를 보고 필요해지면 그때 판단한다.
