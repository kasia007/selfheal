# 0단계 — 원복 기능은 만들지 않는다 (폐기)

이 단계는 원래 "인수 없이 실행하면 이전에 적용한 수정을 되돌릴지 묻는 화면"을 정의했다.
`.heal/history.json` 에 적용 이력을 남기고, `<대상>/.heal/backup/` 에 원본을 백업하고,
인수 없이 실행하면 `원복하시겠습니까? [y/N]` 을 띄우는 설계였다.

**논의 끝에 이 기능 전체를 만들지 않기로 했다.**

## 왜 없앴는가

- **`--apply` 로 실행한 것은 사용자가 이미 승인한 변경이다.** 검증된 diff 를 보고 스스로
  명령을 다시 실행한 결과이므로, 되돌릴 장치를 에이전트가 따로 가질 이유가 없다.
- **되돌리려면 git 이 있다.** `git diff` 로 확인하고 `git checkout --` 으로 되돌린다.
  자체 백업은 git 이 이미 하는 일을 더 나쁘게 다시 하는 것이다.
- **실수로 덮어쓸 경로가 없다.** 기본 동작이 원본을 건드리지 않으므로(G6), "모르는 사이에
  파일이 바뀌었다" 는 상황 자체가 발생하지 않는다.

## 무엇이 사라졌는가

| 폐기된 항목 | 내용 |
|---|---|
| P0-1 | 인수 없이 실행 시 원복 확인 화면 |
| P0-2 | `--apply` 시 `.heal/history.json` 에 적용 이력 기록 |
| P14-1 | `--apply` 시 `<대상>/.heal/backup/` 에 원본 백업 |
| P14-2 | 위 이력을 0단계가 읽는 연결 |

구현되어 있던 `_load_history` · `_attempt_revert` · `HISTORY_PATH` 도 `src/agent.py` 에서
제거했다. 이력을 쓰는 코드가 애초에 없어서 항상 `None` 을 읽는 죽은 경로였다.

## 지금 동작

인수 없이 실행하면 원복 화면 없이 **곧바로 1단계(경로 입력)** 로 간다.

```
$ ./run.sh

📁 검수할 폴더 또는 파일을 입력하세요
   > ./data/samples/py-index
```

## 검증

| 무엇 | 어떻게 | 통과 기준 |
|---|---|---|
| 대화형 진입 | `./run.sh` (인수 없이) | 원복 화면 없이 경로를 물어봄 |
| 비대화형 | 표준입력을 비운 채 인수 없이 실행 | 묻지 않고 exit 3 |
| 승인 후 되돌리기 | `--apply` 후 `git checkout -- <파일>` | 원본으로 복구됨 (에이전트가 아니라 git 이 한다) |
