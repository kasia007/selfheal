# 8단계 — 버그 리포트 작성 (S8)

`src/agent.py:325 bug_report_node` 에 이미 구현되어 있다 — LLM 호출 1회로 "무엇이 왜
터졌는지"를 문단으로 정리한다.

```python
state.bug_report = self._ask(
    "다음은 테스트가 실패한 코드입니다. 버그 리포트를 작성하십시오.\n"
    f"[언어] {state.language}\n"
    f"[파일] {Path(state.target_file).name}\n"
    f"[소스]\n{state.current_source}\n\n"
    f"[테스트 실패 출력]\n{_tail(state.test_output)}\n\n"
    "핵심 정보만 담은 간결한 문단으로 답하십시오. 코드는 포함하지 마십시오."
)
```

이 리포트는 두 번 쓰인다 — (1) S9(메모리 검색)의 질의어 원재료, (2) 새 패턴을 저장할 때
(S10 이후) 본문 재료. 그래서 "코드는 포함하지 마십시오"가 중요하다. 코드가 섞이면
저장되는 패턴이 특정 파일에 종속돼 재사용성이 떨어진다.

## 확인한 것 — 입력 재료가 충분한가

`state.current_source`(수정 전 전체 소스) + `state.test_output`(실패 로그)만 넘긴다.
7단계에서 여러 후보 파일이 있을 수 있다는 걸 알게 됐지만, 리포트는 **실제 처리 대상
파일 하나**(`state.target_file`)에 대해서만 작성한다 — 지금 범위(1개 처리)와 일치하고,
새로 바꿀 것이 없다.

## 결론 — 새 코드가 필요 없다

기존 동작이 설계와 정확히 일치한다. 7단계와 마찬가지로 "여러 파일을 순서대로 처리"로
범위를 넓히는 순간에만 이 노드도 파일별로 반복 호출하도록 다시 볼 필요가 있고, 그건
별도 단계(다중 파일 루프)의 몫이다.
