# 19단계 — 가드레일: 비밀값 마스킹 · 프롬프트 인젝션 (체크리스트 #6, G10·G11)

체크리스트 확실 충족이 5개(#1·#3·#10·#11·#12)라 권장 "6개 이상"에 하나 모자랐다.
#6(가드레일)을 채워 6개로 넘긴다. 체크박스 채우기가 아니라 실제 노출 경로가 있어 골랐다 —
에이전트가 사용자 소스 전문을 프롬프트에 넣고, 16단계로 LangSmith 추적까지 붙였으므로
켜져 있으면 그 프롬프트가 제3자 SaaS 에 저장된다.

## 결정 1 — 마스킹은 기록·전송 경로에만, 프롬프트 본문은 원본 유지

가장 중요한 설계 판단이다. 이 에이전트는 파일 **전체**를 재생성한다(12단계). 마스킹된
소스를 모델에 주면 모델은 마스크가 든 파일을 그대로 돌려주고, `--apply` 는 **사용자
코드에 `***` 를 써 버린다.** 그래서 Bedrock 프롬프트는 원본 그대로, `.heal/trace.log`·
콘솔·LangSmith 로 나가는 사본만 마스킹한다.

`test_수정_결과에는_마스킹이_섞이지_않는다` 가 이 결정의 핵심 검증이다 — 비밀값이 든
소스로 `--apply` 까지 실행해, 적용된 파일에 `***` 가 없고 원본 비밀값이 그대로 남는지 본다.

## 결정 2 — LangSmith 로 나가는 사본은 `hide_inputs`/`hide_outputs` 로 가린다

처음에는 "메타데이터만 가리면 되나" 로 시작했지만, 실제 위험은 LangChain 트레이서가
**자동으로 캡처하는 호출 입력(메시지 원문)**이었다. `langsmith.Client` 가 정확히 이 용도의
`hide_inputs`/`hide_outputs` 콜백을 제공한다는 것을 실측으로 확인했다.

```python
client._hide_inputs({"messages": [{"content": "password = ..."}]})
# → {"messages": [{"content": "***"}]}
```

다만 `Client` 는 프로세스당 한 번만 만들어지는 전역 싱글턴
(`langsmith.run_trees.get_cached_client`)이라, 추적을 켜는 시점(`configure_tracing`)이
다른 코드보다 먼저 실행되어야 반영된다. 이미 만들어져 있으면 조용히 포기한다 — 마스킹이
안 되는 것이 실행을 막을 이유는 아니다.

## 결정 3 — 인젝션은 차단이 아니라 데이터/지시 분리 + 기록

"무시하고" 같은 문구는 정상 코드 주석에도 나오므로, 탐지되면 거절하는 방식은 오탐에
취약하다. 대신 `wrap_untrusted()` 로 신뢰할 수 없는 입력(소스·테스트 출력)을 구분자로
감싸 "데이터이지 지시가 아니다" 를 프롬프트에 못 박고, 탐지된 문구는 `state.injection_flags`
에 기록만 한다. **진짜 방어는 이미 있는 구조적 가드레일**이다 — 인젝션이 성공해도 테스트
파일은 못 고치고(G1), 승인 없이 원본에 못 쓰고(G6), 무관한 심볼을 지우면 거부된다(G9).

구분자 위조 방어도 뒀다 — 입력 안에 우리 구분자 문자열이 이미 있으면 이스케이프해,
악의적 입력이 가짜 종료 구분자로 자신을 위장하지 못하게 한다.

## 결정 4 — 새 의존성 없이 정규식으로

`detect-secrets`·`presidio` 는 무겁고, 다루는 대상이 소스 코드라 탐지 범위가 좁다(AWS
키·JWT·사설키 헤더·`password=`류 대입·LangSmith 키·Bearer 토큰). 오탐이 나도 코드가
망가지지 않는다(결정 1에 따라 기록 경로만 바꾸므로).

## 구현

- `src/guardrails.py` 신설 — `mask_secrets`·`detect_injection`·`wrap_untrusted`
- `Console._mask` — 화면·`trace.log` 로 나가는 **모든** 문자열이 거치는 단일 지점
- `src/tracing.py _install_redaction` — LangSmith 클라이언트에 `hide_inputs`/`hide_outputs` 설치
- `bug_report_node`·`code_update_node`·`_locate_with_llm` 의 소스·테스트 출력을
  `wrap_untrusted` 로 감쌈
- `locate_node`·`bug_report_node` 에서 `_flag_injection` — 축약 경로(bug_report 건너뜀)도
  놓치지 않게 `locate_node` 에서 한 번 더 검사
- `report.json` 에 `injection_flags` 추가
